# Локальные сервисы: HTTPS, авторизация, WebRTC, службы Windows

## Что это

Умение поднять домашний сервис «как продукт»: свой TLS, вход по паролю, realtime-связь между
устройствами, автозапуск и эксплуатация. Не демо на localhost, а то, что работает после
перезагрузки и доступно с телефона.

## Где подтверждено

- `cases/01-videokamera.md` — HTTPS на 8443 с самоподписанным сертификатом (автогенерация,
  перегенерация, выбор между двумя сертификатами), Basic Auth на страницы, статику и WebSocket
  с constant-time сравнением, WebRTC-аудио в обе стороны, автозапуск службой Windows через NSSM
  с перезапуском через 5 с, ротация логов по 1 МБ, PWA-вьюер с service worker.
  18 коммитов, +4 569 / −1 198 строк, 40 файлов, 6 автопроверок.
- `cases/02-normcontrol-kb.md` — HTTPS-хостинг статики на GitHub Pages с CI-деплоем, доступ
  к контенту без установки софта, публичный сайт с 53 коммитами истории.
- `cases/03-echelon-mini-game.md` — клиентская работа с медиа-API браузера (Web Audio):
  собственный AudioContext, уважает пользовательский переключатель звука.
- `cases/07-echelon-remote-pipeline.md` — локальный HTTP-сервер выдачи результатов, доступный
  с телефона и ноутбука по приватной сети.

## Уровень

**Продвинутый.** Обоснование:

- Работающий сервис, а не прототип: служба Windows с автоматическим стартом, ротацией логов
  и утверждённой процедурой перезапуска (описана в README на 307 строк).
- Безопасность применена не формально: constant-time сравнение пароля, whitelist публичных
  PWA-файлов сделан осознанно (иначе Android не ставит приложение под Basic Auth).
- Realtime-связь: WebRTC с обработкой граничных случаев (зритель подключился позже камеры,
  звук заблокирован браузером, «Звука нет» вместо зависшей кнопки).
- Эксплуатация: 18 инструментов диагностики (сертификат, порт, ntfy, firewall, синтаксис),
  обёртка для задач с правами администратора — агент работал без прав и не ломал систему.
- Живой второй пример: публичный сайт с автоматическим деплоем и ИИ-конвейером в CI (кейс 02).
